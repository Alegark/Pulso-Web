# Política de seguridad

## Reportar una vulnerabilidad

No abras un issue público para una vulnerabilidad de seguridad. Usa GitHub Private Vulnerability Reporting para el repositorio o contacta al mantenedor por un canal privado indicado en su perfil de GitHub. Incluye una descripción breve, el impacto observado y los pasos mínimos para reproducirlo con datos sintéticos. No publiques detalles explotables antes de coordinar una corrección.

## Alcance

Son relevantes los fallos que afecten la aplicación publicada en `https://pulso-web.pruebassoftware.workers.dev/`, el Worker y sus endpoints, el manejo de sesión y almacenamiento del navegador, la importación de playlists, y las dependencias o componentes distribuidos por este repositorio. Indica si el caso ocurrió en la instancia pública o en una ejecución local, junto con navegador, dispositivo y versión cuando se conozcan.

No accedas a cuentas, mensajes, bibliotecas o dispositivos de otras personas; no realices pruebas destructivas ni recolectes datos ajenos. Usa únicamente tus propias cuentas y datos de prueba autorizados.

## Información privada

Nunca incluyas secretos, tokens, cookies, contraseñas, códigos de acceso, sesiones de Telegram, `api_id`, `api_hash`, valores de `YOUTUBE_API_KEY`, audio personal ni datos privados en un reporte. Redacta esos valores antes de adjuntar logs o capturas. Si necesitas demostrar un problema relacionado con una credencial, describe el tipo de dato y sustituye su valor por un marcador ficticio.

El mantenedor acusará recibo y coordinará la investigación y divulgación de acuerdo con la información disponible; no se promete un plazo de respuesta o una recompensa.
